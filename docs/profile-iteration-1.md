# Профиль — первая итерация (1/3)

Ответственный: AntonA22. Эпик: [#36](https://github.com/shaggybee/iOS-FakeNFT/issues/36). [Общая доска](https://github.com/users/shaggybee/projects/1).

## Реализовано

- Основной экран профиля: загрузка фото, имени, описания, сайта и количества NFT/лайков.
- Подключение к общему TabBarView.
- Редактирование имени, описания, сайта и фото по URL; удаление фото.
- Валидация имени и HTTP(S)-адресов, запрет небезопасных схем URL.
- PUT только изменённых полей; массивы nfts и likes при редактировании профиля не перезаписываются.
- Обновление главного экрана после сохранения.
- Подтверждение выхода без сохранения, блокирование повторного сохранения во время запроса.
- Состояния загрузки/ошибки с алертом и повтором, pull-to-refresh.
- Открытие сайта в WKWebView внутри SwiftUI-контейнера.

Списки «Мои NFT» и «Избранные NFT» ещё не реализованы: на первой итерации показаны их счётчики; переходов в незавершённые экраны нет. Эти части запланированы на вторую и третью итерации соответственно.

## Архитектура и требования

SwiftUI + MVVM с `@Observable`; UI-модели изолированы `@MainActor`. `ProfileServiceImpl` — actor, модели профиля и запросы — Sendable. Сеть использует async/await без GCD и completion-блоков. UIKit не используется для вёрстки профиля; UIViewRepresentable нужен только для WKWebView, как предусматривает ТЗ.

Используется подготовленный командой сетевой клиент. Добавлена обратно совместимая поддержка `application/x-www-form-urlencoded`; существующий JSON DTO-путь сохранён. Минимальная версия целевого приложения — iOS 17.0.

## Проверки

Xcode 16.3, iPhone 16 / iOS 18.4:

- Сборка Debug — успешно.
- 15 unit-тестов — успешно.
- 3 UI-теста — успешно: сохранение профиля, выход без сохранения, ошибка загрузки и повтор.
- Эти же 15 тестов бизнес-логики дополнительно прошли в изолированном macOS SwiftPM-окружении.
- Снимки профиля, редактора и ошибки извлечены из xcresult. Они используют **тестовые данные** через явный DEBUG launch argument; обычный запуск всегда использует настоящий сервис. Подмена не включается автоматически при сбое API.

Внешнее ограничение: GET `/api/v1/profile/1` с выданным когортным токеном 22.10.2026 вернул **HTTP 502** примерно через 20 с. Поэтому работа GET/PUT против живого сервера целиком не подтверждена; записи в живой профиль при подготовке не выполнялись. Сохранение и обработка ошибок проверены изолированными тестами. После восстановления API требуется повторить интеграционную проверку.

Некритичные предупреждения исходного проекта: build phase без outputs, обработка PrivacyInfo.xcprivacy зависимости ProgressHUD, отсутствие AppIntents metadata. Компиляция нового кода проходит без ошибок.

## Как запустить

1. Открыть `iOS-FakeNFT-Extended.xcodeproj`.
2. Скопировать `Configurations/Secrets.xcconfig.example` в `Configurations/Secrets.xcconfig` и вписать выданный куратором `API_TOKEN`. Файл исключён из Git.
3. Выбрать схему `iOS-FakeNFT-Extended`, симулятор iPhone с iOS 17+ и запустить.
4. Для тестов выполнить Product → Test либо команду ниже.

```sh
xcodebuild -project iOS-FakeNFT-Extended.xcodeproj \
  -scheme iOS-FakeNFT-Extended \
  -destination 'platform=iOS Simulator,name=iPhone 16' \
  -parallel-testing-enabled NO CODE_SIGNING_ALLOWED=NO test
```

Для ручного просмотра тестового профиля в Debug можно добавить launch argument `--profile-ui-testing`. Для одноразового сценария ошибки — ещё `--profile-fail-first-load`. Это только демонстрация интерфейса; для проверки реальной интеграции аргументы нужно убрать.
