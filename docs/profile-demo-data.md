# Просмотр профиля без API

В Debug-сборке по умолчанию включён демонстрационный режим профиля. Достаточно открыть проект, выбрать схему iOS-FakeNFT-Extended и запустить приложение. API-токен и интернет для профиля, редактирования и списка «Мои NFT» не нужны. Дополнительных надписей режима в интерфейсе нет: экран соответствует макету.

MockProfileService и MockProfileNFTsService реализуют те же протоколы, что и сетевые сервисы. ServicesAssembly сохраняет экземпляры сервисов на время работы приложения. Изменения профиля хранятся в памяти: их можно увидеть после возврата и повторного открытия экрана; после перезапуска возвращается исходный профиль. Сортировка, как и в сетевом режиме, сохраняется в UserDefaults.

Режим затрагивает только сервисы профиля. Внешний сайт пользователя по-прежнему требует соединения с интернетом. Изменение избранного относится к третьей итерации; сердца показывают исходные likes.

## Настоящий API

В Xcode: Product → Scheme → Edit Scheme → Run → Arguments → Arguments Passed On Launch — добавить и включить `--profile-live-api`. Токен задаётся в игнорируемом Configurations/Secrets.xcconfig по образцу Secrets.xcconfig.example.

Release-сборка всегда использует сетевые сервисы. При сбое API автоматической подмены данных нет. Классы моковых сервисов компилируются только в Debug.

## UI-тесты

`--profile-ui-testing` включает изолированные моковые сервисы. Этот аргумент имеет приоритет над `--profile-live-api`. Аргументы ошибок обрабатываются только в режиме UI-тестов:

- `--profile-fail-first-load` — ошибка первой загрузки профиля;
- `--profile-empty-nfts` — пустая коллекция;
- `--profile-nfts-fail-first-load` — ошибка первой загрузки NFT;
- `--profile-nfts-slow-retry` — задержка второго запроса NFT на 60 секунд для проверки ухода с экрана во время повтора;
- `--profile-unavailable-website` — недоступный локальный адрес сайта.
